现实痛点 01 · 传统看表困境 BI 报表疲劳

“只给图表，不给归因与证据”

运营人员面对几十张分散的销售、订单、盘点与设备表，看到门店销售额下跌时，需手动跨表排查根因，耗时极长且易误判：

  • 双因子盲区：分不清是客流订单萎缩还是客单价下滑主导。
  • 缺乏同城标尺：分不清是单店经营失误，还是全区域同步降温。
  • 排查链路割裂：销售表、退款表與设备心跳表彼此孤立，无法一键串联。
真实案例：朝阳 A 店本周销售额突降 -28.0%，传统报表仅标红数字，店长无法一眼识别是订单量暴跌（-31.0%）叠加退款率激增（7.0%）所致。
现实痛点 02 · 通用 AI 问数之坑 口径失真与幻觉

“AI 自由写 SQL 算错账、武断下结论”

直接让通用 LLM 自由生成 SQL 或心算指标，在严肃零售经营场景下会引发三大致命口径事故：

  • 比率均值陷阱：把每日客单价直接取平均，导致大店与小店权重错乱。
  • 脏数据混入：漏扣已退款订单、漏筛员工测试单，把未满30天新店纳入同比。
  • 强行幻觉甩锅：可比门店不足 3 家或缺失成本时，依然强行编造根因。
致命风险：财务与运营口径不一致，仅靠软 Prompt 约束不住 AI 跳步调用，企业根本不敢用于真实周会决策。
现实痛点 03 · 落地执行断层 有报告无闭环

“分析停留在报告，无人跟进与复核”

无论是周会 PPT 还是传统 AI 聊天框，往往止步于“建议加强管理”的空洞套话，缺乏工程化执行闭环：

  • 无人主动值守：设备离线或退款激增时，若无人主动提问便被长期搁置。
  • 缺乏责任契约：没有明确谁去核查、几小时内完成（SLA）、看哪条证据。
  • 没有结果验收：派单后缺乏下一周期的指标自动复核，同类问题反复重演。
管理黑洞：从“发现问题”到“确认修好”之间缺失状态机追踪，导致数据分析无法真正转化为单店利润恢复。

05 · FUTURE EXPANSION VISION & ROADMAP

未来扩展愿景：从“单域智能审计”迈向“全域自治零售大脑”

架构预留标准化契约与 pgvector 扩展底座，支持三阶段平滑演进

⏱ 路演计时：1:45 - 2:00（15秒）
阶段一 · 连接真实世界 (近期) Production Ready

实时数仓与边缘 IoT 网关全面接轨

  • 生产级数据接入：从 CSV/Supabase 种子切片平滑切换至实时 POS 流水、ERP 库存与外部地理/客流 API 适配器。
  • 真实 IoT 边缘网关：将主动监控 Loop 接入智能冰柜温控、门磁与电压传感器，实现秒级硬件故障预判。
  • 企业级协同触达：打通企业微信、飞书与钉钉卡片审批，店长在手机端一键确认行动卡并上传整改照片。
架构优势：当前前后端 API 契约与模块化单体已完全解耦，替换底层数据源零需重写前端与 Agent 编排层。
阶段二 · 多模态与全域扩维 (中期) Multimodal & Supply

多模态视觉巡检 + 业财供应链全链路

  • 多模态视觉审计：融合智能柜摄像头图像识别，自动检测货架缺货率、陈列合规度、异常拿取防损，生成视觉证据 ID。
  • 经营维度扩展：在销售额/退款率基础上，纳入商品保质期损耗、会员复购率、营销活动归因与补货人效指标库。
  • 跨城多租户治理：引入 RBAC 区域权限隔离、多级审批流与 SLA 考核看板，支撑千店级规模化运营。
演进原则：视觉与预测模型同样遵循“只输出带置信度的结构化证据，由确定性规则定级”的安全边界。
阶段三 · 自演进决策飞轮 (远期) Self-Evolving Brain

基于复核结果反哺的自治零售大脑

  • 历史案件向量检索（pgvector）：将每一次结案的异常特征、处置动作与复核改善幅度存入向量库，新发异常自动匹配历史最优 SOP。
  • 策略权重动态校准：根据历史任务复核通过率（Closed vs Escalated），自动评估哪些行动建议真正有效，反哺风险排序模型。
  • 受控多 Agent 协同：在契约稳定后，由审计 Agent、选址 Agent 与供应链补货 Agent 协同推演全局利润最大化方案。
终极愿景：让每一家无人零售小店都拥有一位“算得准、守规矩、盯得住结果”的 AI 首席运营官。
