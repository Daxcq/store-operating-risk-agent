### 关键架构事实（后续维护别搞错）

- 运行时是**纯 Node 单端口**：`vite build` + `vite preview`，`/api/v1/*` 由 `vite.config.js` 的
  `laisen-retail-agent-api` 插件挂在 `configurePreviewServer` 上，与页面同源同进程。
- 数据层**不需要 Python、不需要 Supabase**：`src/services/pipeline.ts` 直接读
  `data/store_operations_daily.csv`（62KB）与 `data/region_cost_input.csv`。
  `data_layer/` 与 `supabase/` 是离线工具，线上零引用。
  `dataLayerClient.js` 会尝试 127.0.0.1:8787，连不上就 3.5s 超时回退——线上属于纯浪费，
  若后续在意首屏耗时可设 `DATA_LAYER_ENABLED=0`。

### 为发布做的改动

1. 新增 `server.mjs`：程序化调用 `vite preview({ root, preview: { port: PORT, host: 0.0.0.0,
   strictPort: true, allowedHosts: true } })`，并 `process.chdir(root)`（否则 `data/*.csv` 读不到，
   会静默退化成兜底数字）。踩过的坑：`configFile` 用 `new URL().pathname` 会被百分号编码，
   必须 `fileURLToPath`。
2. `vite.config.js` 加 `server/preview` 的 `host: 0.0.0.0` + `allowedHosts: true`。
3. `package.json` 加 `"start": "node server.mjs"`。
4. **`requirements.txt` 改名 `requirements-python-tools.txt`**（内容未改，仅加说明）。
   原因：发布平台依赖扫描把 `psycopg2/supabase` 当成运行时依赖，直接判 `unsupported`
   （external-service / PostgreSQL）——是误判。同步更新 `README.md`、
   `docs/DEPLOYMENT.md`、`data_layer/repository.py` 里的引用。
5. `README.md` 增「生产运行（单端口）」小节。

发布命令：`installCmd: npm install`，`startCmd: npm run build && node server.mjs`，port 4173。
