# 高定 UI × AI Agent 前端工程 Prompt

## 角色与目标

你是一名拥有一线互联网产品经验的高级前端工程师、交互设计工程师与设计系统架构师。

请基于当前项目的实际技术栈，对 UI 进行高精度视觉与交互打磨。目标不是堆砌动画或复制设计模板，而是构建一套统一、克制、稳定、细腻的界面体验。

严格遵循以下 10 条设计原则，但必须根据实际字体、浏览器兼容性、动画库和业务场景选择正确实现方式。

## 01. 去除多余边框，建立微明度层级

**设计原则：** 优先通过背景明度、留白、柔和阴影与低对比度细描边建立层级，避免粗硬边框（`2px+`）和纯黑色描边。

参考色板：

- 浅色背景：`#f5f5f3`
- 浅色浮层：`#fcfcfb`
- 深色主背景：`#0b0b0a`
- 深色次级背景：`#151515`
- 深色面板：`#1a1a19`
- 深色浮层：`#20201e`

实施要求：

- 将以上颜色作为候选设计 Token，而不是强制覆盖现有品牌色或行业主题色。
- 优先通过相邻表面的细微明度差异与多层低透明度阴影区分层级。
- 边界确有必要时，使用 `1px` 低对比度描边（或半透明边框 `rgba(...)`），避免在卡片、弹窗或气泡上使用突兀的粗实线边框。
- 禁止使用纯黑 `#000000` 作为默认边框或大面积装饰色，但不应因此禁止所有场景使用纯黑。
- 不能只追求明度接近而牺牲文字可读性、控件可辨识度或无障碍对比度。
- 同一层级的组件必须共享统一的色彩与边线规则。

**验收：** 页面没有粗重黑框或硬边堆叠感，表面与浮层过渡自然，文字和关键控件仍然容易辨认。

## 02. 输入框聚焦：用内外双环建立咬合感

**设计原则：** 避免浏览器默认的高亮外框与产品设计风格冲突，同时杜绝直接 `outline: none` 导致键盘焦点丢失。

实施要求：

- 为输入框、文本域、下拉选择器定义默认、悬停、聚焦、禁用和错误状态。
- 对外层包裹型输入组件（如带图标的 `.search-box`、组合输入框），内部 `<input>` 移除默认边框后，必须在父容器上通过 `:focus-within` 实现相同的双环聚焦状态。
- 聚焦时优先通过双层 `box-shadow`（内环贴合边界 + 外环柔和扩散）体现咬合状态。
- 通过设计系统定义的焦点环替代默认视觉样式，但必须保留键盘用户可识别的焦点指示。
- 只有在自定义焦点样式已正确实现时，才移除原有 `outline`。
- 处理输入框与外层容器之间的 `overflow` 裁切、层叠和阴影冲突。

参考实现：

```css
.input:focus-visible,
.input-group:focus-within {
  outline: none;
  border-color: var(--focus-border);
  box-shadow:
    0 0 0 1px var(--focus-inner),
    0 0 0 3px var(--focus-outer);
}
```

其中变量应根据浅色和深色上下文分别定义，避免硬编码后出现某种背景下几乎看不见焦点的问题。

**验收：** 鼠标与键盘交互状态清晰，独立输入框与组合搜索框聚焦过渡自然，不出现突兀的粗亮描边或无反应状态。

## 03. 暗色模式与深色容器：补偿字体的视觉增重

**设计原则：** 深色背景上的浅色文字容易产生视觉光晕与扩张感，但不能脱离字体特性将所有文字机械减重。

实施要求：

- **主题边界前提：** 若当前项目已支持暗色模式，则在暗色主题下全局应用；若当前项目为**单浅色主题**，仅对既有的深色局部容器（如深色顶栏、深色浮窗头部、深色代码块、深色状态栏）应用视觉减重补偿，**不得为了套用规则而将单浅色项目强行改成局部暗色卡片**。
- **抗锯齿与字色补偿（通用有效）：** 在深色背景容器上优先开启灰度抗锯齿（`-webkit-font-smoothing: antialiased; -moz-osx-font-smoothing: grayscale;`），并使用高不透明度浅色（如 `rgba(255, 255, 255, 0.9)`）替代刺眼的纯白 `#ffffff`。
- **可变字重补偿（按需启用）：** 若项目使用的字体确实支持可变字重（Variable Font）或对应中间字重档位，可以现有字重为基准降低约一个档位（如从 `400` 调整为 `350–375`）。如果字体仅提供标准整百字重（如 `400/500/700`）或为常规中文字体，不要假设设置 `font-weight: 360` 会生效。
- 分别检查正文、标题、代码、数字和辅助信息，不要通过降低字重让小号文字变得纤细难读。
- 使用 CSS 变量统一管理浅色与深色表面的文字渲染差异。

**验收：** 深色模式或深色顶栏/浮窗中的浅色文字干净利落、不发虚膨胀，正文依然清晰可读。

## 04. 流式文本：打造自然的渐显体验

**设计原则：** 让生成中的内容与思考步骤拥有轻柔的显现过程，而不是逐字机械弹出或整块生硬闪现。

目标动画参数：

- 参考持续时间：`90ms`（块级/段落级可放宽至 `140ms–180ms`）。
- 参考缓动曲线：`cubic-bezier(.215, .61, .355, 1)`。
- 参考错峰间隔：`30ms`（仅限有限数量的短条目或步骤块）。
- 初始状态：`opacity: 0`、轻微位移 `translateY(2px)`，可选轻量 `blur`。
- 最终状态：`opacity: 1`、`translateY(0)`、`blur(0)`。

实施要求：

- 先确认当前项目是否已经实现模型流式输出（如 SSE `delta` / `step` 事件）。
- 优先保留原始流式数据链路，不能为了动画延迟文本交付。
- **严禁在流式 Markdown 或富文本渲染器中将全量文本按单字符拆分为独立 `<span>` 节点**，避免破坏中文分词、引起 React 重渲染闪烁或破坏屏幕阅读器与复制体验。
- 默认只对新增内容块（Chunk/Block）、流式思考步骤或刚生成的结论段落应用渐显动画，不得让整个消息气泡在每次更新时重新播放动画。
- 优先使用轻量的透明度和位移动效。模糊效果（`filter: blur()`）应严格限制在少量标题或单块容器上，避免大量节点同时执行模糊滤镜造成掉帧。
- 为流式输出中的光标（Cursor）提供柔和的呼吸或闪烁反馈。
- 对开启 `prefers-reduced-motion: reduce` 的用户提供直接显示的无动画降级方案。

参考 CSS：

```css
@keyframes text-reveal {
  from {
    opacity: 0;
    filter: blur(4px);
    transform: translateY(2px);
  }

  to {
    opacity: 1;
    filter: blur(0);
    transform: translateY(0);
  }
}

.text-reveal {
  animation: text-reveal 120ms
    cubic-bezier(.215, .61, .355, 1) both;
}

@media (prefers-reduced-motion: reduce) {
  .text-reveal {
    animation: none;
    filter: none;
    transform: none;
    opacity: 1;
  }
}
```

**验收：** 流式文本与思考步骤自然渐显，长文本不会因动画堆积而延迟，消息更新不闪烁、不重复播放。

## 05. 行内图标：建立统一的基线对齐

**设计原则：** 行内图标应像文字的一部分自然融入句子，独立按钮图标应精准几何居中，而不是上下漂浮。

实施要求：

- 对行内图标优先采用统一的图标尺寸与基线规则，可从 `vertical-align: -0.125em` 开始微调。
- 根据实际图标的视觉重心、字体大小和图标库（如 Lucide）进行适配，避免行内 SVG 撑高行距。
- 对独立按钮、徽标、步骤节点中的图标使用 `inline-flex` / `grid` 配合 `align-items: center` 居中，并设置 `flex-shrink: 0` 防止挤压变形。
- 检查图标与中文、英文、数字混排时的垂直对齐。

参考 CSS：

```css
.icon-inline {
  display: inline-block;
  width: 1em;
  height: 1em;
  vertical-align: -0.125em;
  flex-shrink: 0;
}
```

**验收：** 行内图标与中英文及数字视觉居中，不撑大行高，不在窄容器中被挤压变形。

## 06. 数字防抖：锁定数字宽度

**设计原则：** 数字变化或列表对标不能导致状态栏、计时器、指标卡片、徽标和按钮位置来回跳动。

实施要求：

- 对所有动态数字、金额、百分比、步骤耗时（`ms`）、计数器、排行榜和对比表格数值列启用等宽数字特性：`font-variant-numeric: tabular-nums;`。
- 即使已声明等宽字体（如 `'DM Mono'`），也应显式加上 `tabular-nums`，防止在中英混排、`%`/`¥` 符号连写或字体未加载回退至系统字体时发生宽度抖动。
- 对固定长度的指标和实时步骤计时器，可根据实际场景预留合理的最小宽度（`min-width`）。
- 数字较长时应允许合理换行或截断，不能以固定宽度掩盖溢出。

参考 CSS：

```css
.metric,
.timer,
.status-number,
.num {
  font-variant-numeric: tabular-nums;
}
```

**验收：** 连续更新的计数器、思考耗时、进度、指标卡片与表格数值对齐工整，不会造成明显横向位移。

## 07. 丝滑折叠：优先使用 CSS Grid

**设计原则：** 折叠面板（如思考过程链、详情抽屉折叠区、FAQ）尽量不依赖 JavaScript 实时测量内容高度，也不直接通过条件渲染生硬卸载 DOM。

实施要求：

- 优先采用 `grid-template-rows: 0fr → 1fr` 的过渡方式实现展开与收起。
- **结构与内边距隔离（关键）：** 网格容器内部必须存在一层纯包装层 `.collapse-grid__inner` 并设置 `min-height: 0; overflow: hidden;`。**严禁在 `.collapse-grid__inner` 上直接设置垂直方向的 `padding` 或 `border`**（否则收起为 `0fr` 时仍会残留空白高度或边线）；所有内边距和顶部/底部分隔线必须放在其内部的再下一层内容容器 `.collapse-grid__content` 上。
- 触发折叠的按钮必须绑定正确的 `aria-expanded` 属性，且收起状态下应通过 `visibility: hidden` 或 `inert` 防止隐藏内容被键盘 `Tab` 键误聚焦。
- 折叠图标（如箭头 Chevron）应使用平滑的 `transform: rotate(...)` 过渡，而非直接替换生硬跳变。
- 不能为了动画强制卸载仍然需要保留状态的组件。

参考 CSS：

```css
.collapse-grid {
  display: grid;
  grid-template-rows: 0fr;
  opacity: 0;
  visibility: hidden;
  transition:
    grid-template-rows 220ms cubic-bezier(.2, .7, .2, 1),
    opacity 180ms ease,
    visibility 220ms;
}

.collapse-grid[data-open="true"] {
  grid-template-rows: 1fr;
  opacity: 1;
  visibility: visible;
}

.collapse-grid__inner {
  min-height: 0;
  overflow: hidden;
  /* 严禁在此层设置垂直 padding 或 border */
}

.collapse-grid__content {
  padding: 10px 12px;
  border-top: 1px solid var(--line);
}
```

**验收：** 展开与折叠自然连续，收起后完全严丝合缝（无残留内边距或双边框），无障碍焦点状态正确。

## 08. 防孤字：改善正文与标题换行

**设计原则：** 优先让浏览器选择更自然的换行位置，减少段落末尾单字成行或标题中的突兀断行。

实施要求：

- **正文与长句：** 在回答正文、诊断说明、卡片描述、列表项与对话气泡容器上启用 `text-wrap: pretty;`。
- **短标题：** 在页面主副标题、卡片标题（`h1`–`h4`）上启用 `text-wrap: balance;`。
- 不要把它理解为绝对禁止孤行或孤字，不得为避免单字换行而导致大面积留白或横向溢出。
- **代码与长标识符隔离：**
  - 代码块 `<pre>` 必须保留适合代码阅读的 `white-space: pre`（或 `pre-wrap`）与横向滚动 `overflow-x: auto`，**不得对 `<pre>` 套用普通正文折行规则**。
  - 行内 `<code>`、长 URL、`trace_id`、`evidence_id` 等长标识符应设置 `overflow-wrap: anywhere` 或 `word-break: break-word`，防止撑破窄卡片。

参考 CSS：

```css
.message-content,
.prose-body {
  text-wrap: pretty;
}

.heading-balanced {
  text-wrap: balance;
}

.message-content pre {
  white-space: pre-wrap;
  overflow-x: auto;
}

.message-content code,
.id-token {
  overflow-wrap: anywhere;
}
```

**验收：** 标题视觉均衡，长段落阅读更自然，窄屏或紧凑浮窗下没有明显的异常断行和横向溢出。

## 09. 动效性格：根据操作建立不同的物理反馈

**设计原则：** 所有动效都应服务于操作语义，不使用一套统一的线性过渡或夸张弹跳覆盖所有交互。

### 拖拽、吸附、浮窗缩放与面板定位

- 弹簧动画库参考参数：`stiffness: 1200`、`damping: 80`。
- 纯 CSS 近似参考：`transition: transform 180ms cubic-bezier(0.22, 1, 0.36, 1), opacity 180ms ease;`
- 目标：快速到位、近似临界阻尼、干脆稳定、不回弹。

### 点赞、勾选、确认采纳与轻量成功反馈

- 弹簧动画库参考参数：`stiffness: 380`、`damping: 18`。
- 纯 CSS 近似参考：`transition: transform 240ms cubic-bezier(0.34, 1.56, 0.64, 1), background-color 160ms ease;`
- 目标：轻微弹性、快速收敛、反馈明确。

实施要求：

- 必须先识别当前项目的依赖列表；**若项目未安装弹簧动画库（如 `framer-motion`），不得擅自新增依赖**，应使用上述 CSS 缓动曲线与关键帧实现等效物理质感。
- 浮窗展开、抽屉滑入与卡片定位应干脆稳定，不产生晃动感。
- 采纳、复制成功、勾选等轻量反馈只允许微幅缩放（如 `scale(0.96) -> scale(1.03) -> scale(1)`），不应造成图标持续振荡或周边布局位移。
- 严格支持 `prefers-reduced-motion: reduce`。

**验收：** 面板与浮窗切换干脆稳定，成功确认反馈轻盈有弹性，不同交互具有明确而克制的动效性格。

## 10. 反馈自熄：让临时状态自动恢复

**设计原则：** 复制、一键填入、状态刷新、轻量保存等短暂反馈应及时出现，并在合适时间后自动恢复。

以复制成功（如复制 `trace_id`、证据编号或诊断结论）为例：

1. 用户触发复制操作。
2. 等待真实复制结果（兼容 `navigator.clipboard` 与回退方案）。
3. 复制成功后切换为对勾图标或“已复制”微弹性成功提示。
4. 约 `2.2s–2.5s` 后平滑淡出。
5. 完成淡出后恢复默认图标和状态。

实施要求：

- 反馈必须绑定真实操作结果，失败时不能显示成功。
- 将成功状态、动画和定时器生命周期统一管理（如封装通用 Hook 或自包含按钮组件）。
- 同一组件在连续触发操作时，必须先清理旧定时器（`clearTimeout`），避免先前操作提前关闭新反馈。
- 组件卸载时必须清理尚未结束的定时器，杜绝内存泄漏与卸载后 `setState` 告警。
- 状态切换与恢复过程中保持按钮或标签尺寸稳定，不引起相邻元素跳动。

**验收：** 成功反馈准确出现，约 2.5 秒后自然恢复，连续点击和组件卸载不会造成状态闪烁或报错。

## 工程执行规则

1. 先检查现有项目结构、组件、样式变量、主题机制和动画库。
2. 先识别问题，再决定是否修改；不得无差别重写全部 CSS。
3. 优先复用现有设计 Token、组件和依赖，不擅自引入未声明的第三方 UI 库。
4. 先完成静态视觉基础（层级、边框、排版、等宽数字），再完成动效（折叠、流式渐显、物理反馈、自熄状态），最后检查布局稳定性。
5. 不得破坏现有 API、业务逻辑、数据契约、消息流式输出或工具调用。
6. 不得仅输出建议；在权限与环境允许的情况下，直接修改代码并完成集成。
7. 对每项修改运行适当的构建、契约检查或自动化测试。
8. 兼容桌面端、窄屏/紧凑视图、浅色区域与深色局部容器。
9. 尊重键盘焦点（`:focus-visible` / `:focus-within`）、文本复制、屏幕阅读器（`aria-*`）和 `prefers-reduced-motion`。
10. 完成后汇报修改文件、实际效果、验证结果和未解决的问题；没有执行的测试不得声称通过。

## 最终验收标准

- 视觉层级统一，没有无意义的粗硬边框。
- 独立输入框与组合搜索框聚焦均有清晰的双环咬合感，且键盘可访问。
- 深色容器与暗色区域文字清晰柔和，开启抗锯齿补偿，不机械地统一减重。
- 流式文本与思考步骤自然显现，不拆碎单字 DOM，不因动画而延迟内容交付。
- 行内图标、动态数字（`tabular-nums`）、CSS Grid 折叠面板与正文/标题排版（`pretty` / `balance`）稳定。
- 浮窗定位、确认采纳、一键复制等反馈符合各自的物理语义且支持 2.5 秒自熄恢复。
- 原有业务逻辑、构建与核心自动化验证全部通过。
- 所有关键结论均以实际代码与验证结果为依据。

现在请检查当前项目并开始实施。先定位问题，再做最小且高质量的修改；不要仅为了满足某条规则而牺牲真实用户体验。
