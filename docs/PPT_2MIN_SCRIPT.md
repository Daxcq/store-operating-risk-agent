## 三、评委高频追问快答锦囊（Q&A Cheat Sheet）

1. **问：你们是如何保证大模型绝对不会算错比率、也不会编造数字的？**
   - **答**：靠三重硬隔离：① **算术隔离**——大模型只负责在 7 个白名单工具间规划参数，所有比率（先聚合分子分母再相除）、同伴中位数分位（`peer_median`）和 ROI 评分全部由 B 层确定性引擎算好；② **输出白名单护栏**——[safety.js](file:///d:/莱森地平线/src/agent/safety.js) 中的 `collectAllowedNumbers` 会自动提取本轮工具返回证据池中的所有合法数值（含百分比换算），一旦 `hasHallucinatedNumbers` 检测到模型输出了证据池外的数字，立即拦截并回退为确定性事实模板；③ **无模型 100% 可用**——即便拔掉网线或不配 API Key，确定性规划器与合成器也能走通完整闭环。

2. **问：为什么 `S004` 门店退款缺失 33% 时单店审计显示 `unavailable`，但其他门店对标时还能保持至少 3 家可比同伴？**
   - **答**：这是我们在 [benchmark.py](file:///d:/莱森地平线/data_layer/benchmark.py) 中专门设计的**双层按指标准入机制（Two-Layer Per-Metric Peer Admission）**。单店审计层面对 `S004` 整体触发 `>20%` 缺失率熔断，返回 `unavailable` 防止把缺数当正常；但在同伴对标层，系统是**按指标逐列过滤**的——`S004` 的退款率虽然缺失被剔除，但它的销售额、订单数、毛利率完整有效，依然保留在朝阳区的同伴池中，既守住了数据质量底线，又避免了高价值商圈因单字段断报而集体跌入 `insufficient`。

3. **问：KV Cache 命中率是怎么在代码里真正落地的？**
   - **答**：我们在 [definition.js](file:///d:/莱森地平线/src/agent/definition.js) 和 [contextBuilder.js](file:///d:/莱森地平线/src/agent/components/contextBuilder.js) 中严格落实了《上下文与 KV Cache 约束》六大铁律：`STATIC_SYSTEM_MESSAGE` 与固定顺序的 7 个工具 Schema 经过 `deepFreeze` 递归字节级冻结，绝不混入时间戳、用户名或动态状态；所有本轮问题、时间窗、记忆与工具结果一律 Append-Only 追加在消息末尾；禁止 `.slice(-N)` 滑动窗口破坏前缀；历史超阈值时由 `compactMessagesIfNeeded` 按 SHA-256 哈希复用确定性摘要，并在 Trace 中实时记录 `prompt_tokens` 与 `cached_tokens` 命中率。
